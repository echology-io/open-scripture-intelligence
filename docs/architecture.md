# Architecture

## Overview

Open Scripture Intelligence uses a layered architecture that transforms raw Markdown Bible text into structured, AI-ready data.

Each layer builds on the one below it. Consumers can adopt any layer independently.

```
Source Layer (Markdown)
       |
       v
Canonical Layer (JSONL)
       |
       v
Chunk Layer (JSONL)
       |
   +---+---+
   v       v
Graph    Embeddings
Layer     Layer
   |       |
   +---+---+
       |
       v
  Export Layer
```

---

## Layer Descriptions

### Source Layer

**Format:** Markdown
**Location:** `source/raw-markdown/`

Raw Bible text stored as human-readable Markdown files. One file per chapter.

File naming: `{book}-{chapter}.md`

Example: `john-03.md`

```markdown
---
translation: WEB
book: John
chapter: 3
---

# John 3

3:1 Now there was a man of the Pharisees named Nicodemus, a ruler of the Jews.

3:2 The same came to him by night, and said to him, "Rabbi, we know that you are a teacher come from God..."

3:16 For God so loved the world, that he gave his only begotten Son, that whoever believes in him should not perish, but have eternal life.
```

Design decisions:
- YAML frontmatter for metadata
- One chapter per file for manageable file sizes
- Verse numbers as prefix for reliable parsing
- Plain text body (no inline markup on verse text)

### Canonical Layer

**Format:** JSONL
**Location:** `canonical/`

The source of truth. Every verse, chapter, and book is a normalized record.

Files:
- `books.json` — 66 book records with metadata
- `chapters.jsonl` — chapter-level records
- `verses.jsonl` — every verse as a structured object

This layer is generated by `scripts/parse_markdown.py`.

### Chunk Layer

**Format:** JSONL
**Location:** `chunks/`

Chunks group verses into retrieval-friendly units.

Three granularities:
- `by_verse/` — single verse (finest grain)
- `by_passage/` — multi-verse passage (natural teaching units)
- `by_chapter/` — full chapter (broadest context)

Passage boundaries follow natural pericope divisions (teaching units, narrative blocks, discourse sections).

### Graph Layer

**Format:** JSONL
**Location:** `graph/`

Scripture represented as a network of relationships.

- `nodes.jsonl` — verse/passage/topic/entity nodes
- `edges.jsonl` — typed relationships between nodes

Edge types:
| Type | Description | Example |
|---|---|---|
| `quotation` | OT quoted in NT | Psalm 22:1 -> Matthew 27:46 |
| `prophecy_fulfillment` | Prophecy and its fulfillment | Isaiah 7:14 -> Matthew 1:23 |
| `parallel` | Parallel accounts | Matthew 19:14 -> Mark 10:14 |
| `thematic` | Shared theological theme | Romans 5:3 -> James 1:2 |
| `allusion` | Indirect reference | Revelation 5:5 -> Genesis 49:9 |

### Embedding Layer

**Format:** JSONL
**Location:** `embeddings/`

Semantic vectors for verse and passage chunks.

Each record contains:
- `id` — matches canonical verse/chunk ID
- `text` — source text
- `embedding` — vector array
- `model` — embedding model used

### Metadata Layer

**Format:** JSON
**Location:** `metadata/`

Theological annotations:
- `topics.json` — topic taxonomy (salvation, covenant, faith, etc.)
- `entities.json` — people, places, concepts with verse references

### Export Layer

**Location:** `exports/`

Pre-built exports for common consumers:
- `obsidian/` — Obsidian vault format
- `app/` — app-ready JSON bundles
- `training/` — ML training datasets

## Data Flow

```
1. Markdown source files are created or imported
                    |
2. parse_markdown.py reads .md files
   -> produces canonical/ JSONL
                    |
3. build_chunks.py reads canonical/
   -> produces chunks/ at three granularities
                    |
4. build_graph.py reads canonical/ + external cross-ref data
   -> produces graph/ nodes and edges
                    |
5. generate_embeddings.py reads chunks/
   -> produces embeddings/
                    |
6. export scripts read all layers
   -> produce exports/ in target formats
```

## Storage Recommendations for App Integration

| Data | Recommended Store | Why |
|---|---|---|
| Verses, chapters, books | PostgreSQL / SQLite | Structured queries, joins |
| Cross-references, relationships | Neo4j / Memgraph / NetworkX | Graph traversal |
| Embeddings | pgvector / Qdrant / Weaviate / Chroma | Vector similarity search |
| Topics, entities | PostgreSQL / Elasticsearch | Faceted search, filtering |
| Cached results | Redis | Fast UI responses |

---

## Design Principles

1. **Markdown first** — human-readable source that anyone can edit
2. **JSONL for data** — streaming-friendly, line-oriented, easy to process
3. **Layers are independent** — adopt any layer without requiring the others
4. **Public domain translations** — no licensing barriers to adoption
5. **Schema over convention** — every field is documented and typed
6. **Extensible** — new translations, metadata, and export formats via plugins
